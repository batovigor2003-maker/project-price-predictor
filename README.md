# Чекбилет

Демонстрационное приложение для выбора момента покупки авиабилета по России. В каталоге 100 тестовых сочетаний маршрута, дат, пассажиров и класса. Для каждого сочетания выдача показывает три варианта перелёта с отдельным прогнозом цены на 7 дней.

## Быстрый запуск

Понадобятся Node.js, pnpm и, для хранения данных в PostgreSQL, Docker Desktop.

```bash
pnpm install
pnpm dev
```

Откройте http://127.0.0.1:3000. Чтобы посмотреть приложение на телефоне, подключите его к той же сети Wi-Fi и откройте `http://<IP-адрес Mac>:3000`. Команда `pnpm dev` принимает подключения из локальной сети. Если Docker недоступен, приложение использует 100 подготовленных сценариев из кода.

## Запуск с PostgreSQL

В корне проекта уже есть локальный `.env`. Если его нет, скопируйте `.env.example` в `.env`. Если PostgreSQL на порту 5432 ещё не запущен, поднимите его:

```bash
docker compose up -d
```

Если контейнер PostgreSQL этого проекта уже работает, не запускайте второй контейнер на том же порту. В обоих случаях затем выполните:

```bash
pnpm db:migrate
pnpm db:seed
pnpm dev
```

Скрипт заполнения добавляет 100 билетов только в пустую таблицу и не удаляет существующие записи.

## Как проверить руками

1. Откройте главную страницу и найдите блок «Что ищут другие 👀» с примерами маршрутов.
2. Нажмите на любой маршрут. Проверьте, что в выдаче три карточки с разными ценами, временем вылета и прогнозами.
3. Для билета туда-обратно проверьте обе строки перелёта в каждой карточке.
4. Нажмите «Изменить» и задайте сочетание параметров, которого нет среди примеров. Приложение покажет сообщение «Билеты не найдены».

## Тестовый поиск реальных рейсов

1. Получите ключ в [кабинете IGNAV](https://ignav.com/dashboard) и добавьте в локальный файл `.env.local` строку `IGNAV_API_KEY=ваш_ключ`. Файл с ключом не нужно добавлять в Git.
2. Запустите или перезапустите `pnpm dev` и откройте http://127.0.0.1:3000. В шапке появится «Тестовый поиск билетов».
3. Выберите Москву и Сочи, будущую дату и один билет в экономе. Нажмите «Найти билеты». С обратной датой приложение ищет билет туда-обратно.

Поиск запрашивает рейсы для рынка США (`market: US`). Прямые перелёты идут первыми, затем отображаются варианты с пересадками. Для билетов туда-обратно учитываются оба направления. Цена отображается в валюте ответа, обычно в долларах. Для цен, которые IGNAV ещё не подтвердил, карточка показывает пометку «Ориентировочная цена». Поиск работает без PostgreSQL. Без ключа приложение открывается в режиме демо.

## Принятые правила демо

Горизонт прогноза составляет 7 дней. Изменение от −5% до +5% включительно считается почти неизменной ценой. Обратная дата необязательна. Рейсы, цены и вероятности в карточках заданы для демонстрации. Метод прогноза на реальных данных пока не определён.

## Выкатка на сервер

Когда изменения попадают в `main`, GitHub Actions проверяет проект, собирает Docker-образ и публикует его в GHCR с полным SHA коммита. Сервер скачивает этот образ, применяет миграции PostgreSQL и запускает приложение. Выкатка проходит успешно, когда [проверка приложения](https://app.checkbilet.ru/health) отвечает по HTTPS со статусом 200 и SHA новой версии. При ошибке откройте журнал запуска во вкладке [Actions](https://github.com/batovigor2003-maker/project-price-predictor/actions).

База PostgreSQL хранится в отдельном томе Docker. На сервере пароль задаётся в файле `~/checkbilet-deploy/.env` строкой `POSTGRES_PASSWORD=...`. Для новой базы значение можно сгенерировать командой `openssl rand -hex 32`. Тестовые данные загружаются отдельно один раз после первой выкатки.

Для ручной проверки откройте [Чекбилет](https://app.checkbilet.ru), выберите один из предложенных маршрутов и проверьте карточки с ценами и прогнозами.
